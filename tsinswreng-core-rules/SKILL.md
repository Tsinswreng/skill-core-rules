## 請求意圖判定

先判定用戶是在詢問、要求方案，還是在授權執行。

以下表述默認為詢問，不授權修改文件或外部狀態:

- 「行不行」、「能不能」、「是否可行」
- 「怎麼做」、「有甚麼方案」、「你覺得呢」
- 「應該怎樣改」但沒有明確要求現在修改

詢問階段只做只讀檢查和分析。 不得使用 `apply_patch`、寫文件、刪除文件、執行會產生項目輸出的建置命令或執行 Git 操作。

### 修改授權

只有用戶明確使用下列意義的動詞時才執行修改:

- 建立、創建、添加、修改、改成、實作、寫入
- 刪除、移除、重命名、執行、建置、完成

明確授權只涵蓋用戶指定的文件、項目和行為範圍。 不要因為前文討論過某個方案，就把後續詢問自動解讀成授權。

用戶同時提出方案和明確修改指令時，方案是約束，修改指令是授權。

### 歧義處理

若無法可靠判定是否獲得修改授權，立即停止在修改前詢問用戶。

提問應簡短指出:

- 目前理解到的請求
- 尚未確定的授權範圍
- 可供選擇的「只分析」或「直接實作」

不要用猜測代替確認。
